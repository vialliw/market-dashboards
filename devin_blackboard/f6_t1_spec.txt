# Implementation plan v4: WellnessCheck.py — post-generation AI-packet validator

v4 addresses round-3 concerns with precise specifications. Separate
script; no GexDashboard.py imports (independent reference implementations);
blackboard cycle F6 (B→C→D).

## 1. Interface (unchanged)

`python WellnessCheck.py <packet.json> [--snapshot raw.pkl] [--report report.json]`
Exit codes: 0 PASS / 0 WARN / 1 FAIL / 2 checker-internal error. Every run
emits a structured report even on FAIL (see §6).

With --snapshot: reconcile raw rows, exact eligibility + reason code verified (FAIL on mismatch). Without snapshot: flag-verdict emitted as 'unperformed (ambiguous without raw rows)' whenever <2 positive-OI strikes; reason-code check always 'unperformed' without snapshot. Tolerance: `abs_err <= max(1e-9, 1e-9*max_magnitude)` — absolute floor 1e-9 covers float64 serialization round-trip error (~1e-15 relative at 1e6 scale is too tight for hand-edited JSON; floor chosen to pass honest rounding, fail real mismatch); tests cover cancellation, rounding, material mismatch | FAIL |
| MAXPAIN-01 | independent canonical recompute: rows filtered to finite strike & finite OI; candidates = sorted unique strikes; pain(s)=Σ call_OI·max(s−K,0)+put_OI·max(K−s,0); argmin = first-min in ascending order; packet max_pain must equal it (exact float== on identical inputs; also report ties count) | FAIL |

## 3. Provenance (unchanged intent, now explicit)

packet_hash (SHA-256 of file bytes), snapshot_hash when supplied,
packet generated_utc, WellnessCheck.py git commit resolved from the
checker's OWN source directory (`git -C <dir of WellnessCheck.py>
rev-parse HEAD`); when the source is not under version control, emit
code_commit:null + a "not version-controlled" provenance note rather than
a wrong/absent value, schema_version,
per-expiry counts {strikes, finite_oi_rows, excluded_rows, stale_iv_rows,
metrics_unavailable}.

## 4. Failure/edge handling (§6 spec)

- Malformed JSON, unreadable file, unsupported schema_version →
  structured report `{overall_status:"FAIL", checks:[{check_id:"INPUT-01",
  status:"FAIL", ...}]}` written if --report path given, exit 1.
- Checker-internal exception → report `{overall_status:"FAIL",
  checks:[{check_id:"CHECKER-ERR", status:"FAIL", note:<repr>}]}` +
  nonzero exit 2; no traceback-only failures.
- Any check whose inputs are absent → status:"unperformed" (not PASS).
- Report written to --report path or `validation/<packet>_report_<ts>.json`;
  artifacts NEVER overwrite the input packet (open output in 'x'-safe mode
  / distinct filename).

## 5. Tests (offline, tests/test_wellness.py)

- Hand-calculated mini-books: 3-strike book with known argmin computed by
  hand; flip crossing cases incl. exact-zero gex (non-material), crossing
  at floor boundary 1e-3, multiple crossings → nearest-spot; constrained
  boundary-hit vs fell_back vs between-strikes selection.
- PASS: TSM fixture packet; WARN: stale generated_utc; FAIL-per-check:
  tampered max_pain/flip/aggregation/IV-provenance/unavailability-flag-on-
  eligible-chain (AVAIL-01b catches false-unavailable)/false-available-on-
  degenerate.
- INPUT-01/CHECKER-ERR paths tested (malformed file, missing file).
- Snapshot reconciliation: real TSM pickle → PASS + counts; mismatched
  snapshot (different ticker data) → FAIL.
